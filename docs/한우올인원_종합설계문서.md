# 한우 올인원 플랫폼 — 종합 설계 문서

> 농가 직접 사용용 / 오프라인 우선 모바일 앱
> 기술 구현(스키마·동기화·API)과 콘텐츠(개량·백신·질병 대응)를 한 문서에 통합

---

## 1. 제품 포지셔닝 — "키우소+"

키우소는 노트·엑셀로 하던 목장 기록을 모바일로 옮긴 서비스로, 농장정보 자동등록, 번식·질병·백신·치료·판매 기록, 기록 기반 알람, 소 검색·우시장 분석 등을 제공한다(전국 약 23만 두 관리). 본 플랫폼은 이 기록·알람 기능을 모두 포함하되, 아래 4가지를 차별점으로 더한다.

| 영역 | 키우소(기존) | 본 플랫폼 추가 |
|---|---|---|
| 기록 | 번식·질병·백신·치료·판매 | 동일 + 사양/체중/사료비 |
| 알람 | 기록 기반 알람 | **월령별·임신주차별 자동 케어 스케줄** |
| 개량 | 제한적 | **KPN 보증씨수소·근친 회피·계획교배 연동** |
| 상담 | 없음 | **AI Q&A 챗봇** |
| 진단 | 없음 | **사진 기반 증상 진단(설사 등)** |
| 이력 | 수기 | **축산물이력제 OpenAPI 자동 연동** |

---

## 2. 전체 기능 모듈

1. **개체 관리** — 이표번호 기준, 혈통(모/부 KPN), 체중 이력, 이동 기록
2. **번식 관리** — 발정·인공수정·임신감정·분만, 발정/분만 알림
3. **사양·사료 관리** — 급여량·단가, 개체별 사료요구율 분석
4. **건강·질병 관리** — 백신·구충·치료·폐사, 자동 접종 스케줄
5. **출하·경영** — 등급 입력, 두당 손익, 농장 전체 수익성
6. **개량(KPN)** — 보증씨수소 선택, 근친계수 확인, 계획교배 시뮬레이션
7. **AI 어시스턴트** — Q&A 챗봇 + 사진 진단
8. **이력 연동** — 축산물이력제 자동 조회로 수기 입력 최소화

## 3. 기술 아키텍처 요약

```
[모바일 앱]  React Native(Expo) 또는 Flutter
   │         └ 로컬 SQLite (오프라인 우선 쓰기)
   ▼
[동기화]     PowerSync / WatermelonDB (양방향, 충돌 해소)
   ▼
[백엔드]     Supabase (PostgreSQL + Auth + Storage + Edge Functions)
   │
   ├─→ Edge Function ─→ 축산물이력제 OpenAPI (EKAPE)
   ├─→ Edge Function ─→ LLM API (Q&A 챗봇)
   └─→ Edge Function ─→ Vision 모델 (사진 진단)
```

핵심 원칙
- **오프라인 우선**: 축사에서 통신이 끊겨도 로컬 SQLite에 먼저 쓰고, 연결되면 동기화
- **관계형 DB**: 혈통·번식·이력이 모두 개체 ID로 엮이므로 NoSQL보다 PostgreSQL 적합
- **외부 API는 서버 경유**: 인증키 노출·CORS 방지를 위해 앱에서 직접 호출 금지

## 4. DB 스키마 상세 (PostgreSQL)

동기화를 전제로, 모든 테이블에 `updated_at`, `deleted_at`(소프트 삭제), `rev`(행 버전), `farm_id`(테넌트 분리)를 공통 부여한다.

```sql
-- 농장(테넌트) & 사용자
create table farms (
  id            uuid primary key default gen_random_uuid(),
  name          text not null,
  farm_reg_no   text,                      -- 농장식별번호(이력제 연동 키)
  created_at    timestamptz default now()
);

create table users (
  id            uuid primary key,
  farm_id       uuid references farms(id),
  name          text,
  role          text default 'owner'       -- owner / worker / vet
);

-- 개체(플랫폼의 중심축)
create table cattle (
  id            uuid primary key default gen_random_uuid(),
  farm_id       uuid not null references farms(id),
  ear_tag       text not null,             -- 이표번호(개체식별번호 12자리)
  name          text,
  sex           text check (sex in ('M','F','C')),  -- 수/암/거세
  breed         text default '한우',
  birth_date    date,
  dam_id        uuid references cattle(id), -- 어미 개체(혈통)
  sire_kpn      text,                       -- 아비 보증씨수소 KPN
  status        text default 'raising',     -- raising/shipped/dead/sold
  acquired_type text,                       -- born/purchased
  acquired_date date,
  -- 공통 동기화 컬럼
  updated_at    timestamptz default now(),
  deleted_at    timestamptz,
  rev           bigint default 1,
  unique (farm_id, ear_tag)
);
create index on cattle (farm_id, status);
create index on cattle (dam_id);

-- 번식 기록
create table breeding_records (
  id            uuid primary key default gen_random_uuid(),
  cattle_id     uuid not null references cattle(id),
  event_type    text not null,             -- estrus/ai/preg_check/calving/abortion
  event_date    date not null,
  sire_kpn      text,                       -- 수정에 사용한 KPN
  ai_round      int,                        -- 수정 횟수
  preg_result   boolean,                    -- 임신감정 결과
  expected_due  date,                       -- 분만예정일(수정일+285)
  calf_id       uuid references cattle(id), -- 분만 시 생성된 송아지
  memo          text,
  updated_at    timestamptz default now(),
  deleted_at    timestamptz,
  rev           bigint default 1
);

-- 건강/백신/치료
create table health_records (
  id            uuid primary key default gen_random_uuid(),
  cattle_id     uuid not null references cattle(id),
  category      text not null,             -- vaccine/treatment/deworm/checkup/death
  name          text,                       -- 백신·약품·질병명
  dose          text,
  route         text,                       -- 근육/피하/경구
  performed_at  date not null,
  next_due      date,                       -- 다음 접종 예정(스케줄 엔진이 채움)
  vet_id        uuid references users(id),
  memo          text,
  updated_at    timestamptz default now(),
  deleted_at    timestamptz,
  rev           bigint default 1
);

-- 체중/사양
create table weight_records (
  id uuid primary key default gen_random_uuid(),
  cattle_id uuid not null references cattle(id),
  measured_at date not null,
  weight_kg numeric(6,1),
  updated_at timestamptz default now(), deleted_at timestamptz, rev bigint default 1
);

create table feed_records (
  id uuid primary key default gen_random_uuid(),
  cattle_id uuid references cattle(id),     -- null이면 군(群) 단위
  feed_type text, amount_kg numeric, unit_price numeric,
  fed_at date not null,
  updated_at timestamptz default now(), deleted_at timestamptz, rev bigint default 1
);

-- 출하/정산
create table shipment_records (
  id uuid primary key default gen_random_uuid(),
  cattle_id uuid not null references cattle(id),
  shipped_at date,
  carcass_weight numeric,                   -- 도체중
  meat_grade text,                          -- 1++ / 1+ / 1 / 2 / 3 / 등외
  yield_grade text,                         -- 육량등급 A/B/C
  price numeric,
  updated_at timestamptz default now(), deleted_at timestamptz, rev bigint default 1
);
```

**분만예정일 자동계산**: 한우 임신기간은 약 285일이므로 `expected_due = ai_date + 285`. 이 값으로 백신·건유 스케줄을 역산한다.

## 5. 오프라인 동기화 & 충돌 처리 로직

### 5.1 전략

농가 환경은 단말이 적고(주로 본인·가족) 동시 편집 충돌이 드물다. 따라서 무거운 CRDT 대신 **행 단위 last-write-wins(LWW) + 소프트 삭제 + 변경 로그** 조합이 적절하다.

- 모든 쓰기는 **로컬 SQLite에 먼저** 기록하고 `pending` 큐에 넣는다.
- 각 행은 `updated_at`(서버 시계 기준 보정)과 `rev`를 가진다.
- 연결되면 마지막 동기화 시점 이후 변경분만 push/pull 한다.

### 5.2 동기화 흐름 (의사코드)

```ts
async function sync(lastSyncedAt: string) {
  // 1) PULL: 서버에서 내 마지막 동기화 이후 변경분 받기
  const remote = await api.changesSince(lastSyncedAt); // {table, rows[]}

  await db.transaction(async (tx) => {
    for (const row of remote) {
      const local = await tx.get(row.table, row.id);
      if (!local) {
        await tx.upsert(row.table, row); // 신규
      } else {
        // 2) 충돌 해소: 더 최신 updated_at이 승리(LWW)
        if (row.updated_at > local.updated_at) {
          await tx.upsert(row.table, row);
        } else if (row.updated_at === local.updated_at && row.rev !== local.rev) {
          // 동시각 충돌 → 서버 우선 + 충돌 로그 적재(농가가 검토)
          await tx.upsert(row.table, row);
          await tx.insert("conflict_log", { table: row.table, id: row.id });
        }
        // 로컬이 더 최신이면 그대로 두고 PUSH 단계에서 올림
      }
    }
  });

  // 3) PUSH: 로컬 pending 큐를 서버로
  const pending = await db.getPending();
  await api.applyChanges(pending);     // 서버도 동일 LWW 규칙 적용
  await db.clearPending(pending);

  return serverNow(); // 다음 lastSyncedAt
}
```

### 5.3 충돌 처리 규칙(권장)

| 상황 | 처리 |
|---|---|
| 한쪽만 수정 | 그대로 반영 |
| 양쪽 수정, 시각 다름 | 최신(`updated_at`)이 승리 |
| 양쪽 수정, 시각 동일 | 서버 값 채택 + `conflict_log`에 남겨 농가가 확인 |
| 삭제 vs 수정 | 삭제(`deleted_at`) 우선, 단 충돌 로그 적재 |
| 폐사·출하 같은 상태 전이 | 비가역 상태 우선(raising→dead는 되돌리지 않음) |

> PowerSync를 쓰면 이 PULL/PUSH·체크포인트 처리를 라이브러리가 대부분 담당하고, 충돌 규칙만 서버 측에 정의하면 된다. 직접 구현 시 위 로직을 그대로 사용 가능.

## 6. 축산물이력제 OpenAPI 연동

축산물품질평가원(EKAPE)이 공공데이터포털을 통해 소·쇠고기 개체정보·이동정보 조회 API를 제공한다. 이표번호만으로 출생일·품종·성별·이동·도축·등급·유통 이력을 받아올 수 있어, 개체 등록 시 **수기 입력을 거의 없앨 수 있다.** 개발계정은 자동승인(일 트래픽 1,000건 수준)이며 서비스 URL은 `data.ekape.or.kr` 기반이다.

> 정확한 엔드포인트 경로·파라미터·응답 필드명은 공공데이터포털의 해당 API 상세 페이지(활용신청 후 제공되는 명세)에서 최종 확인할 것. 아래는 연동 구조 예시.

### Supabase Edge Function (Deno/TypeScript) — 서버에서 프록시 호출

```ts
// supabase/functions/trace-lookup/index.ts
import { serve } from "https://deno.land/std/http/server.ts";

const SERVICE_KEY = Deno.env.get("EKAPE_SERVICE_KEY")!; // 키는 서버 환경변수에만
const BASE = "https://data.ekape.or.kr/openapi-data/service/user/mtrace/breeding/cattle";

serve(async (req) => {
  const { earTag } = await req.json();           // 이표번호(개체식별번호)
  const url = `${BASE}?serviceKey=${SERVICE_KEY}&traceNo=${earTag}&_type=json`;

  const res = await fetch(url);
  const data = await res.json();                 // XML이면 파서로 변환

  // 응답을 우리 cattle 스키마로 정규화
  const item = data?.response?.body?.items?.item ?? {};
  const normalized = {
    ear_tag: earTag,
    birth_date: item.birthYmd ?? null,           // 출생일자
    breed: item.lsTypeNm ?? "한우",              // 품종
    sex: item.sexNm ?? null,                     // 성별
    sire_kpn: item.fbreedNo ?? null,             // 아비(부) 번호
  };

  return new Response(JSON.stringify(normalized), {
    headers: { "Content-Type": "application/json" },
  });
});
```

### 앱에서 호출 (개체 등록 화면)

```ts
async function autofillFromTrace(earTag: string) {
  const { data } = await supabase.functions.invoke("trace-lookup", {
    body: { earTag },
  });
  // 폼에 자동 채움 → 농가는 확인만
  form.setValues(data);

```

이력제 외에 추가로 검토할 공공/협회 데이터: 한우개량사업소(limc.co.kr) 보증씨수소·혈연계수, 한국종축개량협회(aiak.or.kr) 등록·혈통, 국립축산과학원(nias.go.kr) 유전능력 평가 결과(매년 6·12월 갱신).

## 7. AI 기능

### 7.1 Q&A 챗봇

농가의 자연어 질문("우리 3개월 송아지 기침하는데 뭐 해줘야 해?")에 답하는 어시스턴트.

- 구현: 사용자 질문 + **해당 농장의 개체 컨텍스트**(개체 월령, 최근 백신, 증상 기록)를 LLM API에 함께 전달
- 정확도 보강: 본 문서 8장의 백신·질병 데이터를 지식베이스(RAG)로 임베딩 → 환각 방지
- 안전장치: 진단·처방이 필요한 답변에는 "수의사 확인 권장" 고지를 항상 부착

```ts
const answer = await llm.chat({
  system: "너는 한우 사양관리 보조다. 의약품 처방·진단은 수의사 상담을 안내하라.",
  context: { cattle: cattleSummary, kb: retrievedDocs },
  question: userText,
});
```

### 7.2 사진 기반 증상 진단 (설사 예시)

송아지 분변 사진을 촬영하면 색·형태를 분석해 추정 원인과 1차 대응을 제시하고, 위험 신호면 수의사 연결을 권한다.

- 파이프라인: 사진 → Vision 모델(색·점도·혈액 유무 추출) → 8.4 규칙표 매칭 → 추정 원인 + 대응 + 위험도
- **반드시 면책**: "추정 정보이며 확진은 수의사 진료가 필요"를 노출. 혈변·기립불능·심한 탈수는 즉시 수의사 연결 버튼.

### 8.1 백신·예방접종 프로그램

| 백신 | 대상 | 접종 시기 | 용법 | 비고 |
|---|---|---|---|---|
| 송아지설사병 혼합(로타·코로나·대장균) | 임신 어미소 | 기초 1차: 분만 5–6주 전 / 2차: 1차 후 3주 / 추가: 매 분만 2–3주 전 | 2㎖ 근육·피하 | 초유 급여 전 어미 유방 소독 |
| 탄저·기종저 혼합 | 6개월령↑ 전두수 | 매년 2–4월 1회 / 방목 전 추가 | 2㎖ 피하 | 발생우려 지역 |
| 호흡기 혼합(IBR·BVD·PI3·BRSV·헤모필러스) | 송아지·구입우·어미소 | 송아지 1차: 생후 60–70일, 2차: 1개월 후, 추가: 6개월~1년 / 구입우: 즉시+1개월 후 | 1–5㎖ 피하(약제별) | 환절기 일교차 10℃ 이내 관리 |
| 파스튜렐라성 폐렴 | 구입우 | 구입 3일째 1회 | 2㎖ 근육 | 수송열(수송 스트레스) 예방 |
| 아까바네병 | 가임 암소 | 4–6월 1개월 간격 2회 | 5㎖ 근육 | 모기 발생 1개월 전 완료 |

### 8.4 송아지 설사 색깔별 진단 규칙 (사진 진단 엔진용)

| 색/형태 | 추정 원인 | 1차 대응 | 위험도 |
|---|---|---|---|
| 회백색·흰색 물똥 | 대장균(생후 1주 이내), 십이지장염으로 담즙 차단 | 경구 항생제+지사제, 탈수 시 수액·전해질 | 높음(어린 개체 급사 위험) |
| 노란색 | 가장 흔함, 담즙 적당히 섞임(병원체 무관) | 지사제+경구 항생제 | 중 |
| 녹색 | 녹색 조사료 과다, 살모넬라, 담즙 과다 | 항생제+지사제, 필요 시 수액 | 중 |
| 적갈색·혈변·점액 변 | 콕시듐, 살모넬라, 출혈성 장염 | **즉시 수의사** | 높음 |
| 거품 섞인 변 | 로타·코로나 등 바이러스성 | 수액·전해질 보충, 격리 | 중–높음 |

공통 평가: 탈수 정도는 피부 탄력 저하, 눈 함몰, 콧등 점막 건조로 판단. 모든 케이스에서 보온·전해질 보충·충분한 초유가 기본. **혈변·기립불능·심한 탈수는 사진 진단을 건너뛰고 수의사 연결.**

### 8.5 한우 개량(KPN) 정보

- **KPN**(Korean Proven Bull Number): 능력검정으로 선발된 보증씨수소 고유번호
- **EPD**(예상유전전달능력): 씨수소가 후대에 물려줄 유전능력. 예) 도체중 EPD +5.0kg인 A와 −1.0kg인 B로 교배 시, A 자손 도체중이 약 6kg 더 높을 것으로 기대
- **Acc**(정확도): EPD의 신뢰도. 평가 자료가 많을수록 높음
- **4대 경제형질**: 도체중, 등심단면적, 등지방두께, 근내지방도
- **KPN 선발지수**: 위 4형질 육종가를 종합한 지수
- **씨수소 유형**: 육질형(근내지방), 증체형(도체중), 등심형(등심면적), 정육형(등지방), 권장형(육질+육량), 슬림형
- **갱신 주기**: 국가단위 유전능력 평가가 매년 6월·12월 실시 → 최신판 사용 필수
- **근친 회피**: 암소의 아비 KPN을 알고, 혈연(근친)계수가 낮은 보증씨수소를 선택. 근친계수가 높으면 열성 송아지 위험 증가
- **계획교배**: 암소 유전체 분석으로 형질 강·약점을 파악한 뒤, 약점을 보완하는 KPN 정액을 선택 → 앱에서 "가상 교배 결과 시뮬레이션" 기능으로 구현 가능
